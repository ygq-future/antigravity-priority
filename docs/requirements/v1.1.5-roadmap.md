## 2. 缺陷修复详细设计 (Bug Fixes Detailed Spec)

### 2.1 BUG-01：配额探测 (TriggerProbe) 后快照未生成导致前端凭证卡片消失

#### 缺陷根因
在 `internal/runtime/production_runner.go` 中，当请求模式为 `TriggerProbe`（即点击“刷新配额”）时，后端收集完配额证据并持久化到缓存后，直接执行 `return nil` 提前退出。  
**后果**：完全跳过了后续 `PlanFreshOnly` 计算与 `r.setDualSnapshot(dualSnap)` 逻辑，并将 `latestResult` 覆盖为空对象。前端在探测完成后调用 `refreshDashboard()` 拉取 `/snapshot/latest` 时得到空列表，导致卡片全部消失。

#### 技术修复
1. 调整 `production_runner.go` 管道执行顺序：在保存 `store.SaveAtomic` 后，无论何种 Trigger 模式，均无条件执行双组 Plan 计算与 `r.setDualSnapshot(dualSnap)`；
2. 为 `TriggerProbe` 构建包含 `primarySnapshot` 的完整 `apply.Result`，并落盘到 `store.SetRuntimeSnapshot`；
3. 确保探测完成后前端重新拉取快照时，凭证卡片始终 100% 完整展示最新探测配额。

---

### 2.2 BUG-02：重置优先级 (Reset) 后快照未同步与即时写回误拦截

#### 缺陷根因
1. 用户调用 `POST /reset`（重置优先级）时，后端清除了 CPA 宿主中的 `priority` 字段，但未同步更新内存中的 `latestDualSnapshot`。前端刷新后拉到的快照依然保留旧的 `target.priority`（显示 100），造成“重置未生效”假象；
2. 前端 `triggerRun("apply")` 存在静态检查 `if (changes.length === 0)`，由于重置后快照未同步生成 diff，前端直接弹 Toast 提示*“当前凭证状态与优先级已是最优，无需写回”*，强制用户必须先点一次“试运行”才能写回。

#### 技术修复
1. 重构 `Runtime.ResetAllPriorities`：
   - 遍历清除宿主优先级后，将内存中所有凭证标记为 `Priority = 0, PriorityMissing = true`；
   - 重新基于当前配额缓存执行 `PlanFreshOnly` 并调用 `r.setDualSnapshot(dualSnap)`；
2. 前端解除误拦截：移除前端对 `changes.length === 0` 的强行本地拦截，由后端执行严格 diff 比较并返回真实的写回变更结果。

---

### 2.3 BUG-03：配置中心表单多语言覆盖与自定义下拉未同步导致回显失效

#### 缺陷根因
1. HTML 模板中自定义下拉触发器标签（如 `#customIntervalLabel`、`#customCfgModelLabel`）写死了 `data-i18n="optInterval15m"` 和 `data-i18n="optGemini"`。当页面加载或切换语言执行 `applyLanguage()` 时，标签文案被无条件覆盖回默认值；
2. `renderDynamicConfigForm` 在回显数据时仅更新了隐藏 `<select>` 的 `value`，没有更新 `.custom-select-option` 菜单项上的 `.selected` 高亮类名。

#### 技术修复
1. 清除自定义下拉标签上的硬编码 `data-i18n` 属性，统一由 `updateCustomIntervalDisplay()` 和 `updateCustomCfgModelDisplay()` 进行 i18n 翻译与文案绑定；
2. 在表单回显与下拉切换函数中，增加对 `.custom-select-option` 列表的遍历，确保 `.selected` 样式与当前选中值严格同步；
3. 页面初次加载时异步请求 `/config`，确保接口返回后精准回显。

---

### 2.4 BUG-04：导航栏“刷新”按钮未主动同步 CPA 宿主凭证文件

#### 缺陷根因
原导航栏顶部的“刷新”按钮仅从插件本地内存与缓存中读取 `/snapshot/latest`，根本未调用 CPA 宿主的 `ListAuthFiles` 接口。若用户在宿主中新增或删除了凭证，管理界面完全无法感知。

#### 技术修复
1. 后端新增 `Runtime.SyncHost` 核心用例与 `POST /sync` 管理接口；
2. 顶栏“刷新”按钮（`btnRefresh`）触发时主动发起 `POST /sync`，从 CPA 宿主拉取最新凭证文件列表，结合本地配额缓存即时生成全新双组快照并返回渲染。

---

### 2.5 BUG-05：宿主禁用凭证 (Disabled on Host) 丢失配额抓取与倒计时展示

#### 缺陷根因
在 `internal/priority/planner.go` 的 `initialItems` 中，当 `credential.Disabled == true` 时，直接执行 `continue` 提前跳过，未提取该凭证的 `PlanType`、`R5h`、`R7d` 以及双窗口重置倒计时时间，导致被手动禁用的凭证显示为 `unknown` 且所有进度条为 0。

#### 技术修复
1. 在 `initialItems` 中，对 `credential.Disabled == true` 的凭证依然完整提取其 `evidence` 配额、真实 `PlanType` 与倒计时；
2. 保持其 `Disabled = true`、`Priority = -1` 以及 `Reason = "disabled on host"`，确保调度器不激活该凭证，但 UI 上完整呈现其真实额度与重置时间；
3. 前端完善 i18n 翻译：`disabled on host` 汉化为 `宿主已手动禁用`。

## 3. 功能增强详细设计 (Feature Enhancements Detailed Spec)

### 3.1 FEAT-01：多维度自适应调度打分算法优化与自适应分档

#### 现状痛点
在原单维度紧迫度模型 $\text{Urgency} = \frac{R_{\text{7d}}}{T_{\text{7d}}}$ 中，量纲为 `1/hour`，计算结果普遍在 `0.001 ~ 0.015` 之间。在默认 `0.05` 容差下，所有正常活跃账号（如 7d 剩 7% 的 `rikacccccc` 与 7d 剩 73% 的 `owocccccc`）两两差值均小于 `0.05`，被全部判定为同一档，统一赋予了 100 分。

#### 复合打分数学模型
引入复合评分模型 $S_{\text{composite}}$，综合四大核心维度：
$$S = w_1 \cdot P_{\text{weekly}} + w_2 \cdot R_{\text{7d}} + w_3 \cdot R_{\text{5h}} + w_4 \cdot A_{\text{5h}}$$

其中：
1. **周相对燃尽压力比 ($P_{\text{weekly}}$)**：
   $$P_{\text{weekly}} = \frac{R_{\text{7d}}}{\max(T_{\text{7d}}, 0.5) / 168.0}$$
   以 168 小时（7 天）为基准量纲。$P_{\text{weekly}} > 1.0$ 表示剩余时间里额度偏多需加速消耗；$P_{\text{weekly}} < 1.0$ 表示额度消耗过快需保护。
2. **周绝对余量比例 ($R_{\text{7d}}$)**：$R_{\text{7d}} \in [0.0, 1.0]$，确保全局剩余过低的账号获得显著惩罚分；
3. **5 小时短窗可用度 ($R_{\text{5h}}$)**：$R_{\text{5h}} \in [0.0, 1.0]$，保证短窗充裕凭证优先抗并发；
4. **5 小时短窗自愈加速度 ($A_{\text{5h}}$)**：$A_{\text{5h}} = 1.0 - \min\left(1.0, \frac{T_{\text{5h}}}{5.0}\right)$，短窗即将刷新的账号优先消耗。

*默认权重分配*：$w_1 = 0.40, w_2 = 0.30, w_3 = 0.20, w_4 = 0.10$。

#### 动态分档与阶梯分值分配
* 候选账号按复合得分 $S$ 降序排列；
* 维持 `UrgencyTolerance` 容差聚类机制：当相邻凭证得分差 $\Delta S \le \text{Tolerance}$ 时，分配相同优先级以启用 CPA 宿主原生轮询负载均衡；
* 当 $\Delta S > \text{Tolerance}$ 时，跨档递减优先级，形成清晰的阶梯分层（如 100 -> 98 -> 92 -> 88 -> 65）。

### 3.2 FEAT-02：凭证卡片实际优先级与目标/预测优先级双显架构

#### 界面视觉规范
凭证卡片右下角优先级区域重构为**主次双显 + 状态 Tag** 架构：

```
[优先级展示规范]
+-------------------------------------------------------------+
| 实际: [100 / 未设置 / 已禁用]  |  目标: [98]  [待写回]         |
| 状态原因: fresh remaining positive                          |
+-------------------------------------------------------------+
```

1. **实际优先级 (`Actual Priority`)**：
   - 提取自 `item.current.priority`；
   - 若宿主未设置（`PriorityMissing = true` 或 $\le 0$）：显示 `[未设置]`；
   - 若宿主已禁用：显示 `[已禁用]`；
2. **目标/预测优先级 (`Target/Predicted Priority`)**：
   - 提取自 `item.target.priority`；
   - 切换至预测视图时显示 `预测: 98` 并附带 `[🔮 预测]` 徽章；
   - 处于主控组且宿主实际值与目标值不一致时，附带 `[待写回]` 琥珀色状态徽章。

### 3.3 FEAT-03：凭证时序采样数据历史看板与抽屉模态框

#### 功能与交互设计
1. **卡片入口**：在凭证卡片的徽章行右侧提供 `📊 采样` 按钮；
2. **采样抽屉模态框 (`#samplesModal`)**：
   - 标题展示凭证名称与 AuthIndex；
   - 异步调用 `GET /samples?auth_index=xxx`，一次性拉取该凭证在 `gemini` 和 `claude_gpt` 两个模型组下的历史时序采样；
   - 在弹窗内按账号维度并行呈现 Gemini 与 Claude/GPT 的采样时序表格：
     - `#`：采样序号；
     - `采样时间`：精确到秒的本地化时间戳；
     - `5h 余量`：绿色加粗百分比；
     - `7d 余量`：蓝色加粗百分比。
3. **空状态处理**：初次冷启动尚无连续探测样本时，展示友好空状态文案 *“暂无采样历史记录 (需等待连续探测)”*。

### 3.4 FEAT-04：立即写回二确逻辑与变更预览整合

#### 交互流程优化
* **点击主界面“立即写回”**：
  1. 不再弹出简陋的无信息 Confirm 弹窗；
  2. 直接弹出包含所有待更新账号的优先级与禁用状态变更对比弹窗（标题：`⚡ 确认立即写回优先级`）；
  3. 弹窗底部提供 `确认写回` 按钮；
  4. 用户点击 `确认写回` 后，直接执行写入、关闭弹窗、展示成功 Toast 并刷新数据，**不再弹出冗余的结果面板**。
* **试运行 (Dry-Run) 流程保持稳定**：
  1. 点击“试运行”弹出包含详细配额指标与预测值的完整预览面板；
  2. 面板底部提供“立即写回”按钮，点击后进入上述写回确认流程。

### 3.5 FEAT-05：自动调度暂停时倒计时冻结与多态状态机精准呈现

#### 状态机与倒计时行为
1. **自动调度已关闭 (`AutoApply = false`)**：
   - 状态徽章：`⚪ 自动调度已关闭`；
   - 顶部卡片 & 诊断信息：显示 `调度状态: 自动调度已关闭`，倒计时停止。
2. **用户手动暂停 (`Paused = true`)**：
   - 状态徽章：`⏸ 自动调度已暂停`；
   - 顶部卡片 & 诊断信息：显示 `调度状态: 自动调度已暂停`，倒计时立即冻结，不再跳秒。
3. **时段外休眠 (`Sleeping`)**：
   - 状态徽章：`🌙 调度休眠中 (不在运行时间)`；
   - 顶部卡片 & 诊断信息：显示 `调度状态: 调度休眠中`，倒计时停止。
4. **正常运行中 (`Active`)**：
   - 状态徽章：`🟢 自动调度运行中 (09:00-23:00)`；
   - 顶部卡片 & 诊断信息：正常显示秒级自适应倒计时（`下次调度: 04m 20s`）。

### 3.6 FEAT-06：首页模型组与配置中心主控组默认联动选择

## 5. 后端接口与协议契约演进 (Backend API & Protocol Evolutions)

### 5.1 新增接口契约

#### 1. `POST /v0/management/plugins/antigravity-priority/sync`
* **功能**：主动从 CPA 宿主同步凭证文件列表并重新生成双组快照。
* **参数**：`?antigravity_model_group=gemini|claude_gpt`（可选）。
* **响应**：`200 OK` 返回全量 `DualGroupSnapshot` JSON。

#### 2. `GET /v0/management/plugins/antigravity-priority/samples`
* **功能**：获取指定凭证与模型组的历史滑动窗口采样数据。
* **参数**：
  * `auth_index`（必填）：凭证标识符；
  * `antigravity_model_group`（可选，默认 `gemini`）。
* **响应**：
  ```json
  {
    "auth_index": "auth_ag_001",
    "antigravity_model_group": "gemini",
    "samples": [
      {
        "observed_at": "2026-08-20T10:00:00Z",
        "short_window_reset_at": "2026-08-20T13:09:00Z",
        "short_window_rem": 95,
        "long_window_rem": 85
      }
    ]
  }
  ```

## 6. 前端交互状态机与 UI 规范 (Frontend UX & State Machine)

| 场景 | 触发动作 | 系统交互行为与状态流转 | 用户视觉呈现 |
| :--- | :--- | :--- | :--- |
| **宿主凭证同步** | 点击顶栏 `刷新` | 调用 `POST /sync` -> 拉取宿主文件 -> 更新快照 | Toast 提示“已从 CPA 宿主同步最新凭证文件”，卡片即时刷新 |
| **配额重新探测** | 点击 `刷新配额` | 调用 `POST /run?mode=probe` -> 探测 Google API -> 重新计算双组 Plan | 按钮进入 10s 冷却，卡片无缝刷新数据，**绝不出现空白消失** |
| **重置优先级** | 点击 `重置优先级` | 调用 `POST /reset` -> 清除宿主字段 -> 快照重置为 PriorityMissing | 卡片显示 `实际: [未设置] | 目标: 100 [待写回]` |
| **立即写回** | 点击 `立即写回` | 弹出包含各凭证变更的预览弹窗 -> 点击 `确认写回` -> 调用 `mode=apply` | 直接执行写入并刷新，Toast 提示成功，不再弹冗余结果窗 |
| **查看采样历史** | 点击卡片 `📊 采样` | 弹出 `#samplesModal` -> 调用 `GET /samples` | 展示该凭证历史采样时序表格与余量衰减 |
| **修改配置回显** | 切换到 `⚙️ 配置中心` | 自动调用 `GET /config` 回显表单 -> 修改并保存 | 刷新页面或切换语言后，表单和自定义下拉框 100% 保持所选值 |
| **调度暂停/恢复** | 点击调度状态徽章 | 切换 Paused 状态并保存到后端 | 倒计时即时冻结并显示 `已暂停`，恢复后继续倒计时 |
